# Podcast Server

Multi-speaker conversational TTS for Starling. A script of turns between up to four named voices goes in; one continuously rendered 24 kHz WAV comes out, with the turn-taking, pacing and intonation of a two-person conversation rather than stitched single lines.

- **Model**: [VibeVoice-1.5B](https://huggingface.co/microsoft/VibeVoice-1.5B) (Microsoft Research, MIT) — Qwen2.5-1.5B + 7.5 Hz σ-VAE speech tokenizers + a diffusion head; up to 4 speakers, ~90 min.
- **Inference**: Hugging Face transformers' native `VibeVoiceForConditionalGeneration` (pinned `transformers==5.19.0`).
- **Port**: 8093, **127.0.0.1 only**.

> ⚠️ Read [Responsible use and licence](#responsible-use-and-licence) before publishing anything this server renders.

## Why this path

| Option | Verdict |
|---|---|
| **VibeVoice-1.5B via transformers** | **Chosen.** Native support merged 2026-08-27 ([huggingface/transformers#40546](https://github.com/huggingface/transformers/pull/40546)), first released in v5.17.0, with fixes through 2026-09-21 (#48487, #48902). Maintained by the transformers team. |
| VibeVoice-1.5B via the community fork | Fallback only. [vibevoice-community/VibeVoice](https://github.com/vibevoice-community/VibeVoice) (MIT) preserves Microsoft's original code; last push 2026-08-29, and its README now points at the transformers checkpoints. |
| Microsoft's own 1.5B code | Gone — Microsoft deleted it on 2025-09-05 after misuse; [microsoft/VibeVoice](https://github.com/microsoft/VibeVoice) now ships ASR and the Realtime model only. |
| VibeVoice-Realtime-0.5B | Not usable here. One speaker per stream, and Microsoft *"Removed acoustic tokenizer to avoid users creating embedding on their own"*, so it can only speak with Microsoft's preset voices. Building our own voice for it would mean working around a stated safeguard. |

**Weights**: transformers loads the converted checkpoint [`vibevoice/VibeVoice-1.5B-hf`](https://huggingface.co/vibevoice/VibeVoice-1.5B-hf) (pinned `d4cd82eb`). That org is **unofficial** ("VibeVoice Community (Unofficial)"; its members include Eric Bezzam, who contributed the transformers port), so the claim that it is Microsoft's checkpoint, key-renamed by transformers' converter, is verified rather than trusted:

```bash
.venv/bin/python scripts/verify_provenance.py
# all 1204 BF16 tensors byte-identical to microsoft/VibeVoice-1.5B @ c00898d2 — none missing, none extra
```

It streams Microsoft's shards off the Hub (nothing written to disk), maps each tensor name through the converter's own mapping (vendored verbatim from transformers@640a08a5 in `scripts/vibevoice_key_map.py`; the wheel does not ship conversion scripts) and compares bytes. Re-run it whenever `PODCAST_MODEL_REVISION` changes.

## Responsible use and licence

- **Licence**: the weights are **MIT** ([model card](https://huggingface.co/microsoft/VibeVoice-1.5B) `license: mit`). The transformers code is Apache-2.0. The voice prompts are Kokoro-82M output (Apache-2.0 model).
- **Microsoft's intended use** — verbatim from the model card:
  > *"The VibeVoice model is limited to research purpose use exploring highly realistic audio dialogue generation detailed in the tech report."*
  >
  > *"We do not recommend using VibeVoice in commercial or real-world applications without further testing and development. This model is intended for research and development purposes only. Please use responsibly."*
  >
  > *"It is best practice to disclose the use of AI when sharing AI-generated content."*

  The card's out-of-scope list: voice impersonation without explicit, recorded consent; disinformation or impersonation; real-time voice conversion; languages other than English and Chinese; background ambience, Foley or music.

  The MIT licence permits commercial use; the card's research-only statement is Microsoft's intent and recommendation. **Whether to publish VibeVoice audio commercially is an owner decision**, not something this server decides.
- **Disclaimer and watermark.** The card states that Microsoft *"Embedded an audible disclaimer (e.g. 'This segment was generated by AI') automatically into every synthesized audio file"* and *"Added an imperceptible watermark to generated audio so third parties can verify VibeVoice provenance."* What we found:
  - **No audible disclaimer** in this pipeline's output — the test render was transcribed and contains only the script's words. No implementation that exists today inserts one: not transformers, not Microsoft's current repo, and not the community fork, which preserves Microsoft's original release code (a grep for `watermark`/`disclaim` finds no such code in any of them). The card's claim therefore most plausibly describes Microsoft's hosted demo, not the open-source code.
  - **No watermarking code** either. The weights are byte-identical to Microsoft's, so anything carried *in the weights* is preserved; it cannot be checked locally because Microsoft publishes no detector (the card points to `VibeVoice@microsoft.com`).
  - This server returns the model's samples unchanged apart from 16-bit quantization. **Never add processing whose purpose is to remove or mask a disclaimer or watermark** — it is a safety measure, not a defect.
- **Disclosure built in**: every WAV carries RIFF INFO tags (`encoder` = `starling podcast-server …`, `comment` = `AI-generated speech. Model: … (VibeVoice-1.5B, Microsoft Research, MIT) …`), and every response carries `X-Podcast-AI-Generated: true`.
- **Voices**: synthetic only (see [Voices](#voices)). Never clone a real person without explicit, recorded consent, and never use the Voxtral presets (CC BY-NC) for published audio.

## Quick start

```bash
cd apps/podcast-server
./init.sh                  # venv + torch 2.14.1 (cu130) + transformers 5.19.0 + model (~5.4 GB → HF cache)
./start.sh                 # FastAPI on 127.0.0.1:8093 — the GPU worker spawns on the first request

curl -s -o out.wav -D - -H 'Content-Type: application/json' \
  -d '{"turns":[{"speaker":"michael","text":"Hi Emma."},{"speaker":"emma","text":"Hi Michael."}]}' \
  http://127.0.0.1:8093/api/tts/podcast

.venv/bin/podcast-tts script.txt -o out.wav       # batch: no server needed
```

`init.sh --no-gpu` installs only the API + mock engine (tests/CI); `PODCAST_ENGINE=mock ./start.sh` serves without a GPU (one tone per turn). Requirements: Python ≥ 3.10 with venv, and an NVIDIA driver new enough for CUDA 13 wheels (RTX 50xx / sm_120 needs CUDA ≥ 12.8; set `PODCAST_TORCH_INDEX` for other GPUs). Disk: venv ≈ 6.0 GB, model 5.42 GB.

## API

### `POST /api/tts/podcast`

```json
{
  "turns": [
    {"speaker": "michael", "text": "Ever wished you could reach your home PC from a hotel browser?"},
    {"speaker": "emma",    "text": "That's what Roomler does."}
  ],
  "seed": 42,
  "cfg_scale": 1.3,
  "diffusion_steps": 10
}
```

| Field | Type | Default | Range / rule |
|---|---|---|---|
| `turns` | array of `{speaker, text}` | — (required) | 1–400 turns |
| `turns[].speaker` | string | — | a voice name from `GET /api/tts/podcast/voices` (case-insensitive); ≤ 4 distinct per request |
| `turns[].text` | string | — | non-empty, ≤ 3000 chars; all whitespace (incl. newlines) collapses to single spaces |
| `seed` | int | `42` | 0 … 2³²−1; same seed + same input → same audio on the same box |
| `cfg_scale` | float | `1.3` | 1.0 … 3.0 (classifier-free guidance) |
| `diffusion_steps` | int | `10` | 1 … 50 |

Unknown fields are rejected (422). Total text ≤ 20 000 chars per request.

**Response** `200`, `Content-Type: audio/wav` — RIFF WAV, **24 000 Hz, mono, 16-bit PCM**, plus:

| Header | Meaning |
|---|---|
| `X-Podcast-Sample-Rate` | `24000` |
| `X-Podcast-Duration-Secs` | audio length |
| `X-Podcast-Generation-Secs` | GPU render time (excludes a cold load) |
| `X-Podcast-Cold-Load-Secs` | present only when this request paid the model load |
| `X-Podcast-Seed`, `X-Podcast-Cfg-Scale`, `X-Podcast-Diffusion-Steps` | the values actually used |
| `X-Podcast-Speakers` | voices in role order, e.g. `michael,emma` |
| `X-Podcast-Model` | `vibevoice/VibeVoice-1.5B-hf@d4cd82eb` |
| `X-Podcast-Truncated` | `true` if the render hit the runaway guard (`max_new_tokens` ≈ 1.1 × chars + 150) before the model ended it |
| `X-Podcast-Peak-Vram-Gib` | torch peak reserved during the render |
| `X-Podcast-AI-Generated` | always `true` |

**Errors** — JSON `{"detail": …}`:

| Status | When |
|---|---|
| 400 | script semantics: unknown speaker (the message lists the voices), a 5th speaker, a limit exceeded |
| 422 | schema: missing/empty fields, out-of-range `seed`/`cfg_scale`/`diffusion_steps`, unknown fields |
| 503 | `reason: blocked` (less than `PODCAST_MIN_FREE_VRAM_GIB` free — another app holds the GPU; retry later), `load_failed`, `load_timeout` |
| 504 | `reason: synth_timeout` (> `PODCAST_SYNTH_TIMEOUT_SECS`; the worker is stopped) |
| 500 | `reason: synth_failed` or `worker_died` (the next request respawns the worker) |

Requests are served **one at a time** (they queue on the GPU). A client that disconnects does not cancel its render.

### Other endpoints

| Route | Purpose |
|---|---|
| `GET /api/tts/podcast/voices` | `{"voices": [{name, file, duration_secs, sample_rate, gender, accent, source}]}` |
| `GET /api/tts/podcast/status` | `state` (`idle`/`loading`/`ready`/`blocked`), `worker_pid`, `cold_load_secs`, `inflight`, `jobs_done`, `idle_unload_in_secs`, `blocked_reason`, `last_error`, … |
| `POST /api/tts/podcast/load` | warm the model now (returns status) |
| `POST /api/tts/podcast/unload` | stop the worker now — frees the GPU; waits for a running render |
| `GET /health` | `OK` |

## CLI

```bash
.venv/bin/podcast-tts SCRIPT -o OUT.wav [--seed 42] [--cfg-scale 1.3] [--diffusion-steps 10] [--server URL]
.venv/bin/podcast-tts --list-voices
```

`SCRIPT` (or `-` for stdin) has one turn per line, `<speaker>: <text>`. Blank lines and lines starting with `#` are skipped, only the first colon splits, and speaker names are case-insensitive:

```
# roomler promo, take 1
michael: Ever wished you could reach your home PC from a hotel browser, without installing anything?
emma: That's what Roomler does. You open a tab, pick the machine, and you're looking at its desktop.
```

By default the CLI renders **in-process** (loads the model, renders, exits, so the GPU is free when it returns). With `--server http://127.0.0.1:8093` it posts to a running server and shares its warm model. It writes the WAV (same format and INFO tags as the API) and prints one JSON line on stdout:

```json
{"out": "out.wav", "sample_rate": 24000, "duration_secs": 24.8, "generation_secs": 137.13, "rtf": 5.53,
 "cold_load_secs": 16.49, "peak_vram_gib": 5.86, "truncated": false, "seed": 42, "cfg_scale": 1.3,
 "diffusion_steps": 10, "speakers": ["michael", "emma"], "turns": 5, "model": "vibevoice/VibeVoice-1.5B-hf@d4cd82eb"}
```

With `--server`, `cold_load_secs` is `null` unless that request loaded the model, and a `request_secs` field is added.

Exit codes: `0` ok · `1` runtime failure (GPU busy, model or server error) · `2` bad script or parameters.

## Voices

| Name | Built from | Length | Character |
|---|---|---|---|
| `michael` | Kokoro-82M `am_michael` | 17.3 s | male, American English |
| `emma` | Kokoro-82M `bf_emma` | 16.2 s | female, British English |

VibeVoice carries each prompt's accent into the render: `emma` is non-rhotic, so she says "Roomler" as "Roomlə" (an ASR hears "Roomla"); `michael`'s "roomler.ai" transcribes exactly. Both are synthetic clips of neutral prose, 24 kHz mono 16-bit, stored in `voices/` with their provenance in `voices/voices.json` (Kokoro 0.9.4, `hexgrad/Kokoro-82M@f3ff3571`, voice id, text, sha256). Regenerate them with `~/kokoro-venv/bin/python scripts/make_kokoro_voices.py` (Kokoro + espeak-ng, CPU).

To add a voice, drop a 24 kHz mono 16-bit WAV (10–20 s of clean speech) into `voices/` as `<name>.wav` (`[a-z0-9_-]`); it is picked up on the next request. Microsoft's demo voices (e.g. `en-Alice_woman.wav`, `en-Frank_man.wav` in the transformers docs) are an option for experiments, but their provenance is unclear, so they are not shipped and should not be published.

## Turn timings

There are none, by design of the model. VibeVoice renders the whole dialogue **in one pass**: the speech for every turn comes out as one continuous `audio_bos … audio_eos` span (verified with a 5-turn script: one segment, 186 audio tokens = 595 200 samples), and the speaker changes are implicit in that stream. The model offers no per-turn boundaries to return.

When turn start/end times are needed (music ducking, captions), align after rendering. In the test render the four speaker changes fall in silences of 0.38, 1.09, 0.40 and 0.53 s, but in-turn pauses of 0.23–0.45 s occur too, so **silence alone is ambiguous**. Match ASR word timestamps against the known script, or combine silences with a speaker cue: pitch separates a male/female pair cleanly. For the record, the test render's turns are 0.00–6.62, 7.00–10.37, 11.46–17.12, 17.52–22.32 and 22.85–24.80 s (silencedetect at −35 dB / 0.2 s plus median F0 per span).

Rendering line by line would give exact boundaries, but loses the conversational prosody this model exists for.

## Lifecycle and VRAM

```
idle ──request / POST load──► loading ──worker ready──► ready ──idle 600 s / POST unload──► idle
                                 │                        │
                         blocked (503) if < 8 GiB free    └─ worker crash/timeout ──► idle (respawn on next request)
```

The model lives in a **spawned worker process**; the API process never imports torch. Unloading ends the worker, so *all* of its VRAM — CUDA context included — returns to the other Starling apps. It needs ≈ 6.3 GiB of VRAM (5.1 GiB resident weights, 5.86 GiB torch peak during a render, plus the CUDA context) and coexists with the Voxtral ASR (~9 GB) on a 24 GiB card, but not with Voxtral TTS + ASR together. One lock serializes load, render and unload; the idle unload never fires while a request is queued or running. If the server is killed, the worker follows (`PR_SET_PDEATHSIG`).

## Performance

RTX 5090 Laptop GPU (24 GiB), WSL2, measured 2026-10-11 on this five-turn script (2 speakers, 390 chars, 69 words), `seed 42`, defaults:

```
michael: Ever wished you could reach your home PC from a hotel browser, without installing anything?
emma: That's what Roomler does. You open a tab, pick the machine, and you're looking at its desktop.
michael: And your machines talk over a private WireGuard network, so nothing sits open on the internet.
emma: It's open source, you can run the server yourself, and it's free for up to three devices.
michael: Find it at roomler.ai.
```

| Metric | Value |
|---|---|
| Output | 24.80 s, 24 kHz mono 16-bit (186 audio tokens × 3200 = 595 200 samples) |
| Cold load (server worker: spawn + import + weights) | 39.8 s first; 28.2 s with a warm page cache (6.8 s import + 17.3 s weights) |
| Cold load (CLI, in-process) | 16.5 s |
| Render | 93–137 s in four runs (RTF 3.7–5.5); 142–177 s (RTF 5.7–7.1) in two runs while other sessions' cargo builds loaded the CPU |
| VRAM | 5.1 GiB resident; 5.86 GiB torch peak while rendering; ≈ 6.3 GiB for the whole worker incl. CUDA context (nvidia-smi delta) |
| Determinism | same seed → bit-identical WAV: cold vs warm request, and server vs CLI |
| Listener check | starling's own Voxtral ASR transcribes all five lines in order, with no added phrase; pitch per span alternates male (118–146 Hz) / female (170–200 Hz) exactly as the turns do |

Rendering is **CPU-launch-bound** on this box: GPU utilisation stays at 6–12 % with the SM clock at 2.2–2.8 GHz, while the worker pins one CPU core. Each language-model forward costs ≈ 130 ms, almost all of it CPU-side dispatch, so the RTF moves with host CPU load. Profile of one render: language model 52 %, diffusion head 15 %, acoustic decoder 12 %, semantic encoder 12 %, the rest 9 %. The untried lever is `torch.compile` with CUDA graphs (transformers' static-cache compile path covers the language model; the diffusion head has fixed shapes), at the price of compile time on every lazy cold start.

## Project structure

```
apps/podcast-server/
  init.sh / start.sh          # setup (--no-gpu, --no-model, --dry-run) / loopback launcher
  podcast_server/
    main.py                   # FastAPI routes + error mapping
    config.py                 # PODCAST_* settings; pinned model + Microsoft reference revisions
    engine.py                 # lifecycle state machine, idle unload, serialization
    worker.py                 # ProcessWorker (spawned GPU child, pipe protocol) + MockWorker
    synth.py                  # torch side: Renderer — only imported by the worker and the CLI
    script.py                 # `<speaker>: <text>` parser, validation, limits, role mapping
    voices.py · wav.py · disclosure.py · gpu.py · download.py · cli.py
  scripts/
    make_kokoro_voices.py     # rebuilds voices/ from Kokoro (run in ~/kokoro-venv)
    verify_provenance.py      # served weights == Microsoft's, bit for bit
    vibevoice_key_map.py      # transformers' converter key mapping, vendored
  voices/                     # michael.wav, emma.wav, voices.json
  tests/                      # 78 pytest — no GPU
```
